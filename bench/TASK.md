# Task: vehicle inventory (estoque), v1

Revenda Certa's first real feature. A signed-in dealer keeps their own vehicle stock: they list it, add a vehicle, edit it, mark it reserved or sold, and delete it.

## Scope

- A vehicle belongs to the signed-in user who created it. A user only ever sees or changes their own vehicles.
- Store vehicles in Postgres through Prisma, as a new model with a migration.
- Server: the HTTP API below.
- Web: an "Estoque" screen that lists the user's vehicles with a status filter, plus a form to add and edit a vehicle. Changing status and deleting both happen from the list or the edit form. UI copy is in pt-BR, and the style follows `idea/design/` where it applies.
- Mobile is out of scope for v1. So are FIPE lookup, photos and multi-store accounts.
- Tests go at every layer where this repo's conventions expect them.

## A vehicle

| field | rule |
|---|---|
| `id` | string, generated by the server |
| `brand` | required, 1–60 characters, trimmed |
| `model` | required, 1–80 characters, trimmed |
| `manufactureYear` | integer, from 1950 to next year |
| `modelYear` | integer, equal to `manufactureYear` or `manufactureYear + 1` |
| `km` | integer ≥ 0 |
| `color` | optional, up to 40 characters |
| `plate` | required. A Brazilian plate in the old format (`ABC1234`) or the Mercosul format (`ABC1D23`). Input is case-insensitive and may contain a dash. It is returned uppercase, with no dash. Each user's plates are unique. |
| `priceCents` | integer > 0 |
| `status` | `available` · `reserved` · `sold`, default `available` |
| `createdAt`, `updatedAt` | ISO-8601 datetimes |

## HTTP API (match exactly)

Every route needs a signed-in session. Without one, it answers 401.

| method & path | body | answer |
|---|---|---|
| `GET /api/vehicles` | — (optional `?status=available\|reserved\|sold`) | 200 `{ "vehicles": Vehicle[] }`, newest first |
| `POST /api/vehicles` | `brand, model, manufactureYear, modelYear, km, plate, priceCents`, optional `color`, `status` | 201 `Vehicle` |
| `GET /api/vehicles/:id` | — | 200 `Vehicle` |
| `PATCH /api/vehicles/:id` | any subset of the writable fields | 200 `Vehicle` (with the same rules as create) |
| `DELETE /api/vehicles/:id` | — | 204 |

- An id that doesn't exist, or that belongs to another user, gets **404**. Don't reveal that the vehicle exists.
- A body that breaks a rule gets **400** in the repo's error envelope.
- A plate the user already has on another vehicle gets **409**, code `CONFLICT`.

## Done when

- The API behaves as specified above, running against a real Postgres with real signed-in sessions.
- The repo's gates pass: `typecheck`, `lint`, `lint:guards`, `test`, `test:contract` and `test:e2e:validate`, plus `test:e2e` if Chromium is available.
